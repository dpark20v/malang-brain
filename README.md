# 말랑뇌 · 치매 예방 놀이터

집에서 혼자서도 할 수 있는 치매 예방 생활습관과 두뇌 자극 게임 사이트입니다.
병원·치매안심센터가 먼 농어촌에서도 인터넷만 있으면 쓸 수 있도록 만들었습니다.

---

## 실행 방법

가장 간단한 방법은 `index.html` 을 더블클릭하는 것입니다.

구글 로그인까지 쓰려면 서버로 띄워야 합니다:

```bash
cd ~/malang-brain && python3 -m http.server 8765
```

→ 브라우저에서 `http://localhost:8765`

---

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 구조 (홈 / 배우기 / 두뇌게임 / 말랑 스트리크 / 도움받기 / 내 기록) |
| `style.css` | 파스텔 색감, 둥근 모서리, 큰 글씨 디자인 |

| `config.js` | 운영자 설정 (구글 로그인, 스트리크 목표) |

## 로그인 방식

### 1. 이메일 계정 — Firebase Authentication (기본)

로그인 화면에서 **이메일 → 비밀번호 → 아이디·이름** 순서로 진행합니다.

- 이메일과 비밀번호를 넣으면 먼저 로그인을 시도합니다.
  - **성공하면** 그대로 들어갑니다.
  - **실패하면** *"가입된 계정이 없거나 비밀번호가 다른 것 같아요"* 라고 알리고
    「처음이에요 · 새로 만들기」/「비밀번호를 다시 넣을게요」 중에 고르게 합니다.
    (Firebase 의 이메일 열거 방지 기능 때문에 미리 가입 여부를 알 수 없습니다)
- 비밀번호는 **6자 이상** (Firebase 규정)
- 비밀번호는 이 코드가 다루지 않습니다. Google 이 관리합니다.
- 계정 열쇠는 Firebase `uid` 입니다.

> 가입 화면에 *"구글·은행 비밀번호는 넣지 마세요"* 경고를 띄웁니다.
> 비밀번호 돌려쓰기를 막기 위한 안내입니다.

#### 예비 방식 (Firebase 를 못 쓸 때)

`config.js` 에 `FIREBASE` 설정이 없거나 인터넷이 끊겨 있으면,
기기 안에서만 동작하는 로그인으로 자동 대체됩니다.
이때 비밀번호는 계정마다 다른 솔트로 `PBKDF2-SHA256 · 150,000회` 해시해
저장하며, 원문은 남기지 않습니다.

> **이 예비 방식은 서버가 없어서** "누가 쓰는지 구분하는 장치"일 뿐,
> 기록을 지켜 주는 보안 장치가 아닙니다.
> `crypto.subtle` 이 필요해 `http://localhost` 또는 `https://` 에서만 동작합니다.

### 2. 구글 로그인 (선택 · 설정 필요)

`config.js` 의 `GOOGLE_CLIENT_ID` 를 채우면 로그인 화면 아래쪽에
구글 버튼이 나타납니다. **비워 두면 버튼이 아예 보이지 않고**,
이메일 계정만으로 아무 문제 없이 동작합니다.

#### 클라이언트 ID 만드는 법

1. <https://console.cloud.google.com> 접속 → 프로젝트 만들기
2. **API 및 서비스 → OAuth 동의 화면**
   - User Type: 외부
   - 앱 이름: 말랑뇌
   - 테스트 사용자에 본인 이메일 추가
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
4. 애플리케이션 유형: **웹 애플리케이션**
5. **승인된 자바스크립트 원본**에 접속 주소를 등록
   ```
   http://localhost:8765
   https://내아이디.github.io
   ```
6. 발급된 `...apps.googleusercontent.com` 을 `config.js` 에 붙여넣기

> 구글 로그인은 `file://` 로 연 페이지에서는 동작하지 않습니다.
> 반드시 `http://localhost` 또는 실제 주소로 접속해야 합니다.

## 기록이 저장되는 곳

저장 위치는 **로그인 여부에 따라 다릅니다.** 푸터 안내문도 이 상태에 맞춰 바뀝니다.

| 상태 | 저장되는 곳 | 다른 기기에서 보이나 |
|---|---|---|
| 로그인함 | **구글 파이어베이스 서버** (Realtime Database, 싱가포르) + 기기 사본 | ✅ 보임 |
| 로그인 안 함 (게스트) | 이 기기 안에만 (localStorage) | ❌ 안 보임 |

서버로 넘어가는 것은 **이메일·이름·아이디와 실천 기록, 게임 점수**뿐입니다.
비밀번호는 Firebase Authentication이 따로 관리하며 이 코드가 다루지 않습니다.

### 동작 방식

화면은 항상 기기의 localStorage를 보고 그립니다(빠르고, 인터넷이 끊겨도 동작).
서버 동기화는 뒤에서 처리합니다.

- **로그인할 때** — 서버 기록을 가져와 기기 기록과 합칩니다
  (실천 개수는 큰 값, 체크는 합집합 → 어느 쪽도 잃지 않음)
- **기록이 바뀌면** — 1.5초 뒤 모아서 한 번에 전송 (통신·쿼터 절약)
- **로그아웃하면** — 서버에 저장된 계정이면 기기 사본을 정리합니다(공용 기기 배려).
  예비 방식일 때는 유일한 사본이므로 지우지 않습니다

### 서버 저장 구조 (Realtime Database)

```
users/<uid>/profile/{name, loginId}
users/<uid>/log/<날짜>            그날 실천 개수
users/<uid>/check/<날짜>/<항목>   체크 여부
users/<uid>/best/<게임>           게임별 최고 기록
users/<uid>/bestStreak            최고 연속 기록
```

접근 제한은 `database.rules.json` 참고 — 로그인한 본인의 `users/<uid>` 만
읽고 쓸 수 있고, 그 외에는 전부 차단됩니다.

### 기기 저장 구조 (localStorage)

```
malang:pref:font        글자 크기 (기기 공통)
malang:pref:profiles    계정 목록
malang:pref:session     지금 들어와 있는 계정
malang:u:<계정>:log            날짜별 실천 개수
malang:u:<계정>:check:<날짜>   그날 체크한 항목
malang:u:<계정>:bestStreak     최고 연속 기록
malang:u:<계정>:best:<게임>    게임별 최고 기록
```

`<계정>` 은 Firebase 로그인 시 `fb<uid>`, 예비 방식일 때 `e<이메일>`,
로그인 전에는 `guest` 입니다.

### 알려진 한계

같은 날 두 기기에서 체크를 **해제**하면 반영되지 않을 수 있습니다.
기록 손실을 막으려고 "한쪽에서라도 했으면 한 것"으로 합치기 때문입니다.

## 배포

- **Vercel** — `main` 에 푸시하면 자동으로 배포됩니다 (설정: `vercel.json`).
  `vercel.json` 에는 브라우저 캐시 규칙만 들어 있습니다. html/js/css/json 은
  매번 새로 확인하게 해서 고친 것이 바로 반영되고, img 는 하루 동안 붙들어
  느린 인터넷에서 사진을 다시 받지 않게 합니다.
  ※ Vercel 은 `vercel.json` 에 모르는 항목이 있으면 배포를 거부합니다.
    JSON 에는 주석을 넣을 수 없으니 설명은 여기에 적어 둡니다.
- **GitHub Pages** — `.github/workflows/deploy.yml` (예비용으로 함께 유지)
